# Task Service

Сервис для управления задачами с HTTP API на Go.

## Что сделано

В проект добавлена поддержка периодических задач.

Выбранное решение:

- обычная задача `task` остается сущностью для работы пользователя
- периодичность хранится в отдельном шаблоне `recurring task`
- по шаблону создаются обычные задачи в существующем трекере
- если у шаблона задан `end_date`, он считается конечным
- если `end_date` не задан, шаблон считается бессрочным

В результате в системе есть два режима генерации задач:

- автоматическая генерация при создании шаблона
- ручная генерация через отдельный endpoint

Поддерживаемые типы периодичности:
 
- каждый `n`-й день
- каждый месяц в определенный день месяца от `1` до `30`
- на конкретные даты
- по четным дням месяца
- по нечетным дням месяца

## Как это работает

Генерация задач выполняется вручную через отдельный endpoint:

- `POST /api/v1/recurring-tasks/generate`

Он принимает диапазон дат и создает обычные задачи по всем активным шаблонам, которые подходят под этот период.

При создании активного шаблона задачи также генерируются сразу автоматически:

- для `specific_dates` - по всем будущим указанным датам
- для остальных типов - от текущей даты или `start_date` до `end_date`, если `end_date` задан

Для бессрочных шаблонов задачи создаются через ручной генератор.

## Два вида генерации

### 1. Конечные шаблоны

Если у шаблона есть `end_date`, он считается конечным.

В этом случае задачи создаются сразу при создании шаблона.

Пример:

```json
{
  "title": "Звонить больному",
  "description": "Контроль состояния пациента",
  "active": true,
  "recurrence": {
    "type": "every_n_days",
    "start_date": "2026-04-18T00:00:00Z",
    "end_date": "2026-04-24T00:00:00Z",
    "interval_days": 1
  }
}
```

Такой шаблон создаст конечный набор задач с 18 по 24 апреля включительно.

### 2. Бессрочные шаблоны

Если у шаблона нет `end_date`, он считается бессрочным.

В этом случае задачи не генерируются бесконечно при создании шаблона. Для них используется ручная генерация по диапазону дат.

Пример шаблона:

```json
{
  "title": "Уборка кабинета",
  "description": "Ежедневная уборка кабинета",
  "active": true,
  "recurrence": {
    "type": "every_n_days",
    "start_date": "2026-04-18T00:00:00Z",
    "interval_days": 1
  }
}
```

Пример ручной генерации:

```json
{
  "from_date": "2026-04-18T00:00:00Z",
  "to_date": "2026-04-24T00:00:00Z"
}
```

В этом случае будут созданы обычные задачи на все даты в выбранном периоде.

## Какие допущения приняты

- периодическая задача хранится как отдельный шаблон
- шаблон не заменяет обычную задачу, а служит источником для ее создания
- изменение шаблона влияет только на будущие генерации
- повторная генерация на тот же период не создает дубликаты
- защита от дублей реализована на уровне базы данных
- для бессрочных шаблонов используется ручной генератор по диапазону дат

- доменная модель и usecase для шаблонов периодических задач

## Требования

- Go `1.23+`
- Docker и Docker Compose

## Быстрый запуск через Docker Compose

```bash
docker compose up --build
```

После запуска сервис будет доступен по адресу `http://localhost:8080`.

Если `postgres` уже запускался ранее со старой схемой, пересоздай volume:

```bash
docker compose down -v
docker compose up --build
```

Причина в том, что SQL-файлы из `migrations/` монтируются в `docker-entrypoint-initdb.d` и применяются только при инициализации пустого data volume.


## API

Базовый префикс API:

```text
/api/v1
```

Основные маршруты:

- `POST /api/v1/tasks`
- `GET /api/v1/tasks`
- `GET /api/v1/tasks/{id}`
- `PUT /api/v1/tasks/{id}`
- `DELETE /api/v1/tasks/{id}`
- `POST /api/v1/recurring-tasks`
- `GET /api/v1/recurring-tasks`
- `GET /api/v1/recurring-tasks/{id}`
- `PUT /api/v1/recurring-tasks/{id}`
- `DELETE /api/v1/recurring-tasks/{id}`
- `POST /api/v1/recurring-tasks/generate`

## Как проверить

Swagger UI:

```text
http://localhost:8080/swagger/
```

Минимальный сценарий проверки:

1. Создать шаблон через `POST /api/v1/recurring-tasks`
2. Вызвать `POST /api/v1/recurring-tasks/generate` с нужным диапазоном, если шаблон бессрочный
3. Убедиться через `GET /api/v1/tasks`, что обычные задачи были созданы

Пример бессрочного шаблона "Уборка кабинета каждый день":

```json
{
  "title": "Уборка кабинета",
  "description": "Нужно убирать кабинет каждый день",
  "active": true,
  "recurrence": {
    "type": "every_n_days",
    "start_date": "2026-04-16T00:00:00Z",
    "end_date": "2026-04-22T00:00:00Z",
    "interval_days": 1
  }
}
```

Пример генерации задач на период:

```json
{
  "from_date": "2026-04-16T00:00:00Z",
  "to_date": "2026-04-22T00:00:00Z"
}
```

После генерации задачи можно посмотреть через:

- `GET /api/v1/tasks`

У обычных задач есть поле `date`, которое показывает, на какую дату была создана задача.
